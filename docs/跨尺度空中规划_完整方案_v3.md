# ScaleNav 方案 v3.2

**ScaleNav: Open-Vocabulary Global Guidance and Scale-Aware Local Motion Planning for UAV Navigation**

**一句话定位**：同一个学习规划器，不切换模式、不调整参数、不停下，在树林和大楼两种尺度的障碍环境里完成 A→B 无先验地图高速飞行。尺度适应性完全由慢层持久自由空间图注入的走廊输入承载，模型本身永远不需要知道障碍的尺度。

---

## 1. 动机

任务定义：无人机从 A 点飞到 B 点，无先验地图，机载 RGB-D，高速连续飞行。环境跨度从树木、树林（分米到米级间隙）到墙体、大楼、建筑群（十米级以上的绕行拓扑）。

现有方法的问题：

1. **学习型局部规划器的决策尺度小于绕行拓扑的尺度**。以 YOPO 为代表，规划视野约 10 m（2×radio_range），遇到大楼时转弯必然太晚，实测绕不过去。这不是调参问题，是结构问题。
2. **无记忆**。单帧深度进、轨迹出，上一帧看到的楼有多宽立刻丢失，在视野受限的岔路口只能靠赌。
3. **无任务进度概念**。goal 被裁在视野范围内，网络从输入上无法区分"中途的一个点"和"终点本身"，接近终点不减速。
4. **传统分层方案的代价**。建图加全局规划要停下来建图重规划，做不到连续高速；"大障碍 OBB、小障碍 OCC"的混合表示需要一个脆弱的尺度判断阈值（if obstacle_size > threshold），这正是要避免的东西。

设计原则三条：

- 尺度适应性全部由输入承载，模型结构与参数不变；
- 所有场景共用同一组超参数，明文写出；
- 任何时刻存在可执行动作，退化行为是减速和移动中观测，不是悬停。

### 2.1 慢层：持久自由空间球图

图结构以 EPIC（SYSU STAR Lab + HKU，RA-L 2025，开源）的自由空间表示为基座：碰撞自由球覆盖自由空间，球心聚类出顶点，边存储生成时搜索到的见证路径。本方案在它之上做自己的三层东西。形式化如下。

**图即记忆，不建全局融合地图**。不建全局点云、不做体素占据、不建 ESDF。允许短期原始点缓存（NanoMap 式，数帧窗口），只作为半径估计与当前帧碰撞查询的数据源，不引入单独的未知状态。看不见的空间保持乐观可通行；当前深度明确看到碰撞时才阻断节点或边。

**节点** v_i = (c_i, r_i, q_i)：球心、半径、置信度。半径取到最近障碍的距离，由逐帧深度反投影点的 KD-tree 估计（单帧 96×160 = 15360 点，只在生成新节点时算一次）。不为未观测空间额外维护状态。

**边** e_ij = (π_ij, L_ij, d_safe, q_ij, s_ij)：见证路径（生成时在局部点集上 A* 找到并存储）、长度、沿途最小净空、置信度、状态。边复用时按当前帧重新验证 π_ij，验证不过则降级或断开。

**图维护**：沿用 EPIC 的增量机制。空间哈希管理候选区域，union-find 对球聚类出代表顶点，每帧做 V_pre / V_new 差分（V_remove / V_remain / V_insert），只动变化的局部，图世界系持久、跨帧累积。

**可见碰撞校验**：每帧新深度到来时，对当前路线和候选边做投影检查（采样点投影回深度图，比较采样深度与像素深度）。当前帧明确看到碰撞就阻断边；没有看到障碍不创建“未知”状态，边仍保持乐观候选。

**不创建目标人工节点**：图中只允许 `BubbleNode` 聚类得到的真实 `TopoNode`，最终 goal 只作为搜索方向，不以远端节点链或 connectivity spine 的形式插入图。这样增量更新不会反复删除并重建人工终点，也不会因此改变左右绕行同伦。

**搜索**：在从当前 odom 节点可达的真实图上运行滚动目标搜索。对每个可达真实节点 v 计算 `J(v)=||c_v-goal|| + alpha*g(v)`，其中 g(v) 是图上累计边代价，选 J 最小的真实节点作为当前滚动终端，再由搜索父节点还原拓扑路径。边代价 C(e) = w_len·L_ij + w_risk·(1/d_safe) + λ·C_sem(e)。当前深度明确看到碰撞时断边；未观测区域不额外惩罚，边保持乐观候选。图扩展后，滚动终端自然沿 goal 方向继续前移。

路径上直接取搜索输出的近段给 waypoint；当真实图终端进入最终 goal 的局部连接距离时，使用 Bubble A* 验证最后一小段，并把精确 goal 作为终端坐标拼到 witness path。它不是持久图节点，验证失败也不会写入图。飞近后如果当前深度明确发现碰撞，就重新校验并重搜。

连续重规划采用 Bubble Planner 的 Receding Horizon Corridor 原则，但仍在 EPIC 真实图内搜索。不能保存上一周期的 `TopoNode::Ptr` 作为路线身份：EPIC 的 V_remove / V_insert 增量更新会替换节点对象，即使几何走廊没变，旧指针也会全部失效。实现保存上一条 witness path 的世界坐标，将飞机投影到该路径，只保留投影点前方固定长度的 RHC 窗口；当前图中靠近该几何窗口的真实边被重新识别为上一条路线边，并使用 EPIC 原版的零代价复用。上一周期的滚动终端也按世界坐标重新映射到当前真实 `TopoNode`，只要它仍可达且飞机尚未到达，就继续对同一终端做 A*；终端到达、被删除或不可达时，才重新运行目标导向搜索向 goal 扩展。这样保留的是自由空间走廊和绕障同伦，不依赖易失的 C++ 对象地址，也不在搜索后增加 subgoal 低通、左右切换阈值或人工节点规则。

**球基元的适用前提**：场景不存在机体尺度以下的窄缝。大楼、墙体显然满足；树林树干间隙 1–3 m，按机体尺度球链可以覆盖。代价是细树干附近逐帧半径估计偏保守，表现为走廊偏窄，可接受，实验 C 会顺带暴露这个效应。若后续遇到真正窄缝的场景，区域生成器可换成 FRGraph 的方向感知凸区域（见 2.5 升级路径），图维护、碰撞校验、搜索、球链走廊接口全部不变。

视野说明：前视深度相机单帧只覆盖前方，背后与侧面靠图的持久化累积；起飞初期和急转弯后的覆盖缺口按乐观图处理，飞近后再由当前深度剔除明确碰撞边。

**odom 接图约束**：当前飞机不是人工拓扑节点，仍是 EPIC 的瞬时查询节点；它只通过 Bubble A* 生成安全 witness edge 后接入真实 `TopoNode`。若当前点到已知障碍的距离小于 `bubble_astar/safe_distance`，图会明确报告不可达并等待新的观测/位姿，而不会为了发布 subgoal 强行穿过障碍。

Future work 记下一条：路线引导的图精炼闭环。用当前全局路线的切向作为额外候选方向，让图沿计划路径定向生长（search → route → graph → corridor → search），可解开口检测漏检的窄通道。风险是正反馈锁定次优同伦，需保留开口候选保完备性。第一版不上，W1 Gate 若发现开口提取质量差则提前启用。

### 2.2 语义层：开放词汇只在图上

完整数据流：

1. 用户给出一个文本查询，比如"避开建筑"。
2. PEARL 在 RGB 帧上输出该类别的热力图（图像域，开放词汇，推理时可换任意词）。
3. 热力图像素借助深度投影到世界系；图的边沿途采样，累积热力值，得到语义边代价 C_sem(e)。
4. 图搜索总代价 C(e) = w_len·长度 + w_risk·风险 + λ·C_sem(e)，A* 在这个总代价上搜索。换查询词，边代价变，全局路线就变。
5. YOPO 只收到一条不同的走廊，从头到尾不知道"建筑"这个词存在。

开放词汇能力因此是构造出来的：系统中唯一需要训练的部件是 YOPO，其训练数据为纯几何，不含任何类别；PEARL 本身是文本查询的开放词汇模型；图是搜索结构，不经过训练。三个部件没有一个在类别上被训练绑死，推理时换一个从未见过的词，整条链路照样工作，不靠网络泛化。

反面对比：若 PEARL 热力图作为 YOPO 的输入通道，训练集就必须包含特定类别的热力图与对应的避让行为标签；推理时换成未见类别，热力图分布变化，网络响应没有保证。感知开放而行为不开放，能力断在网络边界上。这是 PEARL 从快层挪到图上的原因。

开放词汇带来的能力：

- 同一系统、同一权重，推理时用自然语言改变全局选路，无任何部件为此训练。传统做法要么把类别训进网络，要么建封闭类别语义地图，类别表在训练当天定死。
- 表达纯几何规划器表达不了的任务意图：几何上同样可行的两条路，选哪条取决于任务。几何回答"哪里能走"，语义回答"想走哪条"。
- 语义只动全局路线，局部避障不变，Experiment D 零重训成立。
- 边界明写：语义只参与选路代价，不参与几何碰撞校验。安全不依赖语义，这个边界是卖点不是缺陷。

定位上，端到端语义导航（VLN 一支）靠训练获得语义行为，封闭类别且重训练成本高；本方案把语义放在规划层，开放词汇成为构造性质。

### 2.3 接口：局部走廊

走廊 = 沿全局路线的球链，弧长参数化为 C(s) = {p(s), r(s), d(s)}：中心线位置、局部半径、沿路线到终点的剩余距离。本方案不再额外构造多面体走廊，球链本身就是给 YOPO 的 Corridor 接口。

对选中 witness path 上的采样点 c_k，取有效半径 r_k = max(0, d_occ(c_k) - d_margin)，其中 d_occ 是到已知障碍物的距离，d_margin 是规划安全余量。相邻球满足 ||c_k - c_{k+1}|| <= r_k + r_{k+1} 时，球并集连续；若不满足，就沿该段插入中间球。输出格式为 {(c_k, r_k)}，不需要再定义另一套区域几何。

球链不只用节点球。沿每条边存储的见证路径 π_ij 每隔约半个局部半径采样一个球，半径取该处局部净空。节点球之间若不交叠，只渲染节点球会在球间留下缝隙，而单区间 [near, far] 的掩码编码会把缝隙过填成实体，沿见证路径补球消除这个问题，走廊保真度跟随见证路径而不是节点密度。

走廊在搜索前就以图的形式存在，搜索只是选出一串节点与边并排序，走廊是路线近段的一段球链视图。世界系缓存，图不更新时走廊不动，每帧只做坐标变换后渲染（射线对球链求交，逐球解析解）。EPIC 需要保留选中 witness path 的半径并发布球链，不能只发布无半径的 Path。

走廊跨度 = A* 路线近段 + RHC 窗口内的乐观段（参考 Bubble Planner 的 Receding Horizon Corridor）。走廊对 YOPO 是软引导；乐观段如果在当前深度中明确遇到障碍，就在重搜时被剔除，不需要额外维护未知状态。

#### witness path 与执行 waypoint

`TopoNode` 路径 `[v_0, v_1, ..., v_n]` 是 A* 在拓扑图上选出的节点序列；每条 `TopoEdge(v_i,v_{i+1})` 还保存一串 EPIC 生成的安全 witness 点 `pi_i`。因此执行路径不是简单的节点中心直线，而是：

```text
A* TopoNode 序列
  -> 拼接各边 witness path
  -> 用 EPIC 安全球重叠条件做一次跨边 shortcut
  -> 沿抽稀后的 path 发布滚动 YOPO subgoal
```

witness 点多是正常的内部离散结果，不代表 YOPO 要逐点追踪。shortcut 只在首尾安全球重叠时删除中间点，验证失败则保留原 witness 串，所以不会把绕墙的曲线路径错误地拉成节点中心直线，也不新增第二张图。当前在线实现会记录抽稀前后点数和耗时。

subgoal 是滚动控制目标，不是任务完成信号。EPIC 沿当前 witness path 发布前视目标；YOPO 到达中间 subgoal 后继续接收下一个目标。只有 subgoal 与最终 `/goal_pose` 重合、位置误差小于 `0.5 m` 且速度小于 `0.3 m/s` 时，才进入最终悬停状态。固定高度模式下，最终目标的 z 也投影到 EPIC 当前飞行层，避免任务目标使用地面 z 值时无法完成匹配。

### 2.4 快层：走廊条件化 YOPO

输入三部分：

- **深度通道**（1×96×160，原有）：当前帧观测，回答"现在周围有什么"。
- **走廊掩码通道**（2×96×160）：每个像素存该像素对应射线穿过走廊的深度区间 [near, far]，最大量程归一化，按深度表面截断，NaN 像素不截断，无走廊为零。回答"记着的路线在多宽的范围里走"。
- **obs 向量**：速度(3) + 加速度(3) + 局部 waypoint(3) + 到最终终点直线距离(1) + 沿走廊剩余路径长度(1)。回答"整个任务进行到哪了"。

输出不变：15 条 primitive 的 offset 和 score。ResNet-18 第一层卷积改三通道，新增通道用预训练深度通道权重复制初始化，走廊通道初始贡献为零，训练从原版行为起步。

走廊通道与深度通道的区别：载体相同，语义不同。深度是当前帧的感知，走廊是累积观测算出的决策。截断之后走廊仍携带三样深度没有的东西：视野和量程之外的记忆（提前转弯）、拓扑选择（对称岔路口选哪边）、退化时的替补（NaN 像素处走廊照常渲染）。两者大量冗余的工况（空旷、直线）恰好对应退回原版行为；价值全部出现在两者不一致的时刻。两个通道必须分开，训练让碰撞代价压过走廊代价，"深度管安全、走廊管方向"的优先级自然长出，不手写规则。

### 2.5 设计溯源

慢层以 EPIC 的自由空间球图为基座，本方案的工作是可见碰撞校验、推测节点、goal 加权搜索与球链走廊接口：

| 设计元素 | 出处 | 借什么、改什么 |
|------|------|------|
| 球覆盖自由空间 + 空间哈希 + union-find 聚类 + V_pre/V_new 增量维护 + 边存见证路径 | EPIC（SYSU STAR Lab + HKU，RA-L 2025，开源） | 直接采用其图表示与维护机制；其任务为探索（依赖前沿），本方案为 A→B，前沿逻辑换成 goal 加权与推测节点；其输入为累积 SLAM 点云，本方案改为逐帧深度加短期原始点缓存 |
| 短期原始点缓存、不建融合地图 | NanoMap（MIT，2018） | 引用级别；缓存只作查询源，所有结论按当前帧复核 |
| 可见碰撞校验 | RAPPIDS 的深度图遮挡查询 | 当前深度明确碰撞时阻断边；未观测空间保持乐观，不维护额外未知状态 |
| 推测节点 | 本方案新增 | 深度不连续加 goal 方向生成候选，排除当前深度明确碰撞的候选 |
| 全局搜索与终点加权 | A*（教科书） | 图小，直接搜索；终点距离启发式 + 可见碰撞断边 + 语义边代价 |
| 局部走廊 RHC 截取 | Bubble Planner（IROS 2022） | 引用级别；走廊几何取路线上的球链，沿见证路径补球 |
| 窄缝区域保真（升级路径） | FRGraph（HKUST-GZ，2026，开源） | 球链在窄缝失真时替换区域生成器为方向感知凸区域；其 Lipschitz 区间剖分可作走廊内轨迹连续安全的备选校验 |
| 持久化与拒绝记忆 | FAR Planner（IROS 2022）、SPTM | 引用级别 |

实现上需要精读的只有 EPIC 一篇；其余为相关工作定位用的引用。

## 3. 创新点

### I1（核心）：记忆作为空间区域注入无记忆神经规划器

YOPO 类方法无记忆。我们把记忆存在世界系的持久图里，网络保持无状态，每帧把记忆压缩成与深度对齐的通道喂进去。不用 RNN，不堆帧，训练仍是单帧采样，模拟器管线原封不动，但系统行为有了记忆。

这一点的消融轴因此成为"记忆带宽"：goal（3 个标量）→ waypoint（1 个点）→ corridor（1 个区域）。三者同一网络结构、同一训练管线，唯一变量是注入快层的信息量。消融回答的是一个科学问题：快层需要多宽的记忆通道才能跨尺度。这个切法之前没人做过。

### I2：深度驱动的可见碰撞门控

当前深度明确看到障碍物时，相关边立即阻断并触发重搜；看不见的区域不创建额外未知状态，保持图的乐观候选语义。这条线不需要任何语义进网络，重点验证可见障碍出现后的重搜时延和路径恢复。

与 SCOPE（2026-08，时间上近并发）的区别必须明写：SCOPE 用体素信念地图加激光雷达加传统轨迹优化；本方案用持久自由空间球图加当前深度碰撞门控加学习型快层，不维护严格的未知状态。

### I3：开放词汇语义与运动策略的解耦

语义只进图的代价项，不进网络。训练数据完全解耦：YOPO 的训练数据只有几何和走廊；语义在推理时参与。换查询词（avoid building / trees / powerlines）不重训任何网络，Experiment D 演示这一点。

### I4（附加）：任务进度条件化

obs 里的两个标量（终点直线距离、沿走廊剩余路径长度）让网络学会中途全速、接近终点自然减速、绕大楼时不被很小的直线距离误导而提前减速。同一机制覆盖卖点里"不停下"和"减得下"两端，并修复原版 YOPO 到终点不减速的缺陷。

## 4. 训练方案

采用 YOPOv2-Tracker 的可微代价路线，不使用专家演示。总代价全部可微反传：

- ESDF 碰撞代价（硬安全）
- 平滑代价
- goal 代价
- **走廊代价**：轨迹点超出走廊的违反量惩罚。球链的违反量为 max(0, ‖p − c_k‖ − r_k)，对链上各球取最小，整条走廊的代价可微可反传。J_corr 权重压低，只让走廊引导方向，不压过碰撞代价
- **到达项**：剩余距离小于阈值时，惩罚轨迹末端速度与过冲

走廊数据来源：仿真里用地面真值地图离线计算特权走廊，干净可控；测试时换成真实图的输出。配合走廊扰动增强缩小域差：半径加噪声、随机丢段、整体平移抖动。这与深度腐蚀增强同构——输入通道在训练里见过的脏，测试时就不致命。

数据分布五条纪律：

1. **走廊刻意与 goal 不一致的样本**（绕楼场景）。否则网络学成"走廊约等于 goal 方向"并忽略这个通道。
2. **走廊全零样本**。图上还没有路线时，网络要退回原版 YOPO 行为。
3. **剩余距离全程覆盖**（几百米到半米）。否则进度标量与标签没有因果关系，被网络忽略。
4. **走廊内出现动态障碍的样本**。让深度的硬约束优先级在训练里真实出现。
5. **深度缺失处走廊仍渲染的样本**。走廊掩码在 NaN 像素不截断，深度空白处网络看到的是"无障碍信息 + 走廊说能走"。训练用这类样本验证深度与球链的分工：当前帧明确看到障碍时以深度为准，未观测区域保持乐观。

训练数据因此完全解耦：YOPO 数据集 = 几何 + 走廊 → 轨迹，不含任何语义类别。

## 5. 实验设计

### Experiment A：跨尺度主实验（证明解决了大尺度障碍）

原版 YOPO vs 图+YOPO（waypoint 版即可先行）。场景：空场景、小树、树林、长墙、大楼、建筑群、**混合尺度单次连续飞行**（树林夹大楼，一趟飞完，匀速，无模式标记——主图和主视频）。指标：成功率、碰撞率、路径长、完成时间、最小间隙、重规划频率。全部场景同一组超参数。

### Experiment B：记忆带宽消融

goal 直达 / waypoint / 走廊掩码，三个臂同一网络结构。加"走廊与 goal 冲突"专项场景，检验网络是否真在读走廊通道而不是当噪声忽略。若 corridor > waypoint，证明不是"多给一个点"这么简单。

### Experiment C：腐蚀扫频（退化鲁棒主线）

dropout、噪声、烟雾等级递增，画成功率与速度的降级曲线。对照组（无图、无走廊）在高腐蚀下直接撞。

### Experiment D：开放词汇语义

图上换查询词（无语义 / avoid building / avoid trees / avoid power lines），比较全局路线的合理变化。YOPO 层零重训。

### 基线

原版 YOPO、depthnav（深度 RL，ICRA 2026，必须比）、FAR 加局部规划器的经典分层、SCOPE（若代码可用）。

## 6. 实施路线（对 2026-09-15 截稿，当前 8 月 18 日，约四周）

- **W1：EPIC 式球图验证 Gate**。EPIC 开源代码的输入是累积 SLAM 点云、任务是探索，需要两处改造：输入换成逐帧深度加短期原始点缓存，前沿逻辑换成 goal 加权与推测节点。验证球覆盖质量、增量维护开销、窄视野下的图可用范围，以及当前深度明确碰撞时的重搜行为。Gate 不过则退回自研原型路线继续调。
- **W2：图 + A* + 原版 YOPO 跑通**。waypoint 走现有 goal 通道，零重训，产出 A 组数据。
- **W3：走廊掩码通道 + 可微代价重训**。产出 B 组消融。
- **W4：C 组扫频、D 组演示、写作**。

并行的依赖件照常推进：Colosseum 接口验证、Gate 0 数据审计（200 帧 PEARL IoU + 时延）、腐蚀生成器、模型 trace 修复加契约测试。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| EPIC 代码依赖累积点云地图与探索任务框架，改造成逐帧深度加 A→B 的工作量未知 | W1 设验证 Gate，专测改造后的球覆盖质量与图可用范围；整体不过则退回自研原型继续调；开口提取质量差则提前启用路线引导候选 |
| 未观测区域可能存在尚未看到的障碍 | 保持乐观图语义；飞行接近后由当前深度明确碰撞检查剔除边并重搜，不引入额外未知状态 |
| 逐帧半径在细树干附近偏保守，走廊偏窄 | 可接受，不钻的缝不钻；实验 C 顺带观察该效应 |
| 前视视野导致图覆盖残缺（起飞初期、急转弯后） | 图持久化累积；实验中专门观察转弯后行为 |
| 走廊通道被网络忽略 | 冲突样本加标签因果（训练纪律第 1 条） |
| 特权走廊与真图走廊的域差 | 走廊扰动增强 |
| 走廊版训练延期 | waypoint 版系统 + A/C/D 组实验仍可成文，走廊通道降为补充实验 |
