# GCN 前沿策略与论文定位复盘

## 论文中的核心定位

GCN 是 ScaleNav 的核心贡献之一，不是为了凑完整系统而添加的可选附件。当前论文应当同时突出两个彼此依赖、职责不同的核心：

1. **即插即用的持久拓扑路由层。** 它维护 verified bubble、witness、route memory，并通过 moving local goal 接入 YOPO、EGO-Planner 和 SUPER。
2. **直接工作在在线 topology skeleton 上的 GCN frontier policy。** 它利用拓扑消息传递、全图上下文和时间状态学习 35 m 前瞻的五方向决策，替代手工 frontier ranking。

GCN 只输出 frontier proposal、A* 和碰撞检查保留最终几何决定权，是系统的安全职责划分，不是对 GCN 贡献的降级。更准确的论文叙事是：

> 持久拓扑图提供可迁移的路线记忆和统一决策载体；GCN 在这个载体上学习长距离方向选择；moving local goal 再把已验证路线交给不同局部规划器执行。

当前闭环使用原始 YOPO checkpoint 和 `/scalenav/local_goal`，没有使用 Corridor-conditioned YOPO，也没有向执行器传递 corridor、bubble sequence、route mask 或 graph feature。EGO-Planner 和 SUPER 需要 goal/cloud/command adapter，但 planner core 不修改。因此，“plug-and-play”指统一的目标接口和无需修改规划器算法，并不等于零适配代码。

论文实验按 ICRA 常见结构组织为跨规划器闭环验证、route-layer ablation、GCN policy evaluation 和 online planning workload，不使用 `Q1/Q2/Q3` 式研究问题编号。GCN 的证据链包括：

- 707 帧独立测试集上的 `89.3%` exact accuracy、`89.4%` macro accuracy 和 `99.4%` within-one-column accuracy；
- 最新可复现的验证集扫描选择 `0.00` 切换惩罚；测试集 mean absolute column error 为 `0.115`；
- GCN 批次 10/10 成功，手工 ranking 批次 24/27 成功；两者使用相同 Map2、起点、终点和障碍序列，但批次独立采集且样本量不同，因此只作描述性比较；
- 跨执行器 ScaleNav 批次为 YOPO 10/10、EGO 7/10、SUPER 8/10，证明 topology route layer 的接口兼容性，但不能把三组提升全部单独归因于 GCN。

## 结论

GCN 的模型、35 m 特权标签设计和在线 frontier-policy 接口共同构成核心方法贡献。最终 10/10 成功率则是完整 ScaleNav 链路的系统结果，不能只归因于网络结构本身。

最终效果来自下面这条完整链路：

```text
正确的全局 35 m A* 真值
        +
训练与在线特征一致
        +
GCN 的拓扑编码和时间状态
        +
accepted route 保持、候选 witness 验证、碰撞检查
        +
原有 YOPO 控制器
```

其中最关键的变化是标签从“当前帧下一步怎么走”改成“从当前位置开始，提前 35 m 应该向哪一侧绕行”。如果标签仍然错误，仅仅加深 GCN 或增加隐藏层不能解决提前绕障问题。

## 最终部署的模型结构

当前线上使用：

```text
frontier_gcn_map2_35m.pt
input_dim = 20
architecture = legacy
```

这里的 `legacy` 不是旧的错误模型，而是当前部署检查点采用的结构名称。具体结构位于 [train.py](./train.py)：

1. 两层带边权的 `WeightedGCN`。
2. 每个节点保留自身特征，同时聚合拓扑邻居信息。
3. 对整张图做 mean pooling，得到当前图的全局上下文。
4. `GRUCell` 接收图上下文和上一帧的五方向选择，保持时间连续性。
5. 对五个虚拟候选节点分别打分，输出五个方向的 logits。

五个类别按从左到右排列为：

```text
column 0: 左前  +40 度
column 1: 左前  +20 度
column 2: 正前   0 度
column 3: 右前  -20 度
column 4: 右前  -40 度
```

在线 GCN 只输出 `0..4` 的方向列。它不生成轨迹、不替代 A*，也不直接判断碰撞；A*、witness 和下游碰撞检查仍然拥有最终决定权。

## 借鉴的 GCN 算法来源

本项目借鉴的是 [ICLR 2026 Blogpost: RL with GNNs](https://iclr-blogposts.github.io/2026/blog/2026/rl-with-gnns/) 中“用 PyTorch Geometric 构造 GNN policy”的基本方法。该示例的图编码器使用 `torch_geometric.nn.GCNConv`，其理论基础是 Kipf 和 Welling 的 [Semi-Supervised Classification with Graph Convolutional Networks](https://arxiv.org/abs/1609.02907)：在加入 self-loop 后，用归一化邻接矩阵聚合邻居特征，再经过线性变换和非线性激活。

因此，我们的模型属于：

```text
经典谱域 GCN / GCNConv 风格的消息传递网络
        + 图级 pooling
        + GRU 时序状态
        + 五方向策略头
```

它不是：

```text
GAT（没有 attention head）
GraphSAGE（没有采样聚合器）
Transformer/GNN Transformer（没有 self-attention）
```

训练代码中的 `WeightedGCN` 是对 `GCNConv` 思路的轻量、可控复现，而不是直接调用 PyG 层。它使用拓扑边的显式权重进行消息聚合，加入单位 self-loop，按目标节点的加权度归一化，然后执行 `Linear`；两层之间使用 ReLU。这样做是为了让训练和在线 ROS 节点使用完全相同的输入、边权和数值行为，同时避免把 PyG 作为在线部署依赖。

与博客示例相比，本项目的主要扩展是：

1. 节点不是抽象的游戏状态，而是 ScaleNav skeleton node 和五个虚拟 frontier candidate。
2. 边权来自拓扑几何关系。模型接口保留 `safe_columns` mask，但当前特权数据生成和在线部署都将五列设为 `true`；可达性和碰撞安全由下游 A* 检查。
3. GCN 输出先做整图 mean pooling，再由 `GRUCell` 融合上一帧方向，降低左右抖动。
4. 策略头只对五个候选列打分；GCN 不负责生成轨迹，A*、witness 和碰撞检查仍是最终约束。

更准确地说，博客文章提供的是“GNN policy 的实现范式”，经典 GCN 提供的是图卷积算子；ScaleNav 在此基础上构造了面向 frontier 方向选择的 imitation-learning policy。博客中的示例并没有提供本项目的五方向标签、35 m 特权 A* 真值或在线规划逻辑，这些部分是 ScaleNav 自己设计的。

## 模型结构到底贡献了什么

### 有实际帮助的部分

**拓扑消息传递。**

候选方向不是独立的五个图像分类区域，而是连接到 skeleton graph 的虚拟节点。GCN 可以看到候选节点连接到哪一段拓扑、附近节点的度数、距离 mission goal 的关系以及图的整体形状。

**候选之间的共享表示。**

最终模型先编码整张图，再对五个候选方向分别打分。这样五个方向是在同一个图上下文中比较，而不是五个相互独立的分类器。

**时间状态。**

GRU 接收上一帧选择，降低左右方向在相邻帧之间来回跳变的概率。最新可复现的离线时序评估在验证集上选择 `0.00` 的额外切换惩罚，测试集 exact/macro accuracy 为 `89.3%/89.4%`，mean absolute column error 为 `0.115`。强制使用 `0.05` 时，exact/macro accuracy 为 `89.1%/89.3%`，因此不作为论文主结果。离线分类指标不应直接等同于在线成功率。

### 不能归因于模型结构的部分

最终模型仍然是两层 GCN，而不是更深的 `strong`、`hybrid` 或 `joint` 结构。代码中虽然保留了这些实验结构，但当前 10/10 成功批次部署的是 `legacy` 检查点。因此不能说“加深网络后才成功”。

目前没有在同一数据集、同一训练划分、同一线上参数下对四种结构做严格消融，所以不能从现有日志计算出结构本身带来的独立百分点提升。现有证据更支持这样的判断：

> GCN 结构让拓扑和时间信息能够被利用；标签、特征一致性和执行链路修复决定了它是否学到了正确的行为。

## 为什么早期效果低

### 早期标签是局部的

早期数据主要基于当前 skeleton/局部图，目标接近当前帧的下一步方向。这会让模型在障碍物已经靠近时才改变方向，不能学习“提前很远绕开”。

### 早期类别严重不平衡

旧数据集的标签分布大致为：

```text
[13, 90, 1780, 110, 20]
```

模型输出正前方就能得到较高普通准确率，但左右绕行类别几乎没有学到。对应的一个旧模型测试结果约为：

```text
普通准确率       58.4%
Macro Accuracy  27.8%
相邻一列以内     96.0%
```

Macro Accuracy 低说明模型对少数方向类别不可靠，正是早期在线选择左右绕行不稳定的原因。

### 训练和在线输入曾经不完全一致

后续加入了 yaw、机体坐标下的节点位置、节点到 mission goal 的机体坐标等特征。最终输入是 20 维，训练和在线都使用同样的归一化、候选节点连接方式和列顺序。

如果标签是机体坐标系方向，而输入只有世界坐标，模型必须自己推断坐标变换，训练会明显变难。

## 真正有效的标签修复

最终标签由 [collect_privileged_dataset.py](./collect_privileged_dataset.py) 生成：

1. 使用完整的 Map2 静态点云，而不是某一帧的深度图。
2. 体素化并按无人机尺寸膨胀障碍物。
3. 从当前 odometry cell 到真实 mission goal 做普通 8 邻域 A*。
4. 取路径上至少 `35 m` 之后的点，而不是 `path[1]`。
5. 将该点转换为机体坐标系，并映射到五个方向列。
6. 没有完整可行 A* 路径的帧直接丢弃，不把不可达样本强行贴标签。

最终 Map2 数据集有 `5337` 个样本，标签分布为：

```text
[937, 1293, 1216, 1230, 661]
```

这个分布比早期数据平衡得多。最终静态地图标签的离线结果为：

```text
严格五分类准确率      89.3%
Macro Accuracy       89.4%
相邻一列以内          99.4%
原始 planner 匹配率   22.2%
```

这里的 `22.2%` 不是说原始 planner 不安全，而是说明原始 planner 的即时 frontier 选择与“静态全局地图 35 m 前瞻方向”不是同一个目标。

## 在线系统修复

模型准确率提高后，还需要让规划器正确使用 GCN 输出。关键修改如下。

### GCN 只替换 frontier 方向

GCN 变化不会清空当前已经验证过的 `accepted route`。它只是给下一次 frontier 搜索提供方向提示。

这避免了每次 GCN 从 column 1 变成 column 2 时，规划器都被迫立即丢弃正在执行的路线。

### 候选 witness 失败时保留 incumbent

新候选路线必须通过执行路径碰撞检查。如果候选失败，而原路线仍然可达且拓扑边仍然有效，则保留原路线，不发布空路线或错误的替代路线。

### accepted route 的安全预测采用连续确认

当前 accepted route 前方预测到不安全时，先累计证据；只有连续两帧确认不安全才强制重规划。单帧点云抖动不会立刻导致路线切换。

### 修正左右方向符号

统一了训练、GCN 节点、Graph frontier 排序和 RViz 箭头的列方向定义，保证 column 0 是左前、column 4 是右前。

### 保守的安全距离

最终稳定批次使用 `safe_distance=0.61 m`。之前试过 `0.4 m`，成功率反而下降，说明候选方向正确并不代表执行路线有足够的控制净空。

## SUPER 结果为什么不能直接反驳 GCN

后续使用：

```bash
STACK=scalenav_super bash scalenav_ws/src/aut_test/run_0_140_continuous.sh --count 10
```

时出现了 0/8 或更低的结果。这不能直接归因于 GCN，原因是 SUPER 使用了不同的执行器链：

1. 初始 SUPER 脚本把 Graph 的语义输入错误接成了用于 RViz 的 BGR 图，Graph 报告 `invalid contract: encoding=bgr8`，当时退化成 geometry-only。
2. 修复 topic 后，GCN 和语义候选确实正常工作，单架测试成功。
3. 批量 SUPER 仍出现 `OptimizationBakTrajInPolytopes failed`、backup trajectory 优化失败以及早期碰撞。

因此当前可以确认的是：

```text
GCN + 原有 Route-YOPO：最终 10/10
GCN + SUPER：主要暴露 SUPER 执行器/goal bridge/备份轨迹问题
```

两者不能混合解释。

## 换一张地图会怎么样

当前 GCN 不读取地图名称，也没有显式的 Map2 ID。它读取当前在线 skeleton graph、飞机位姿、mission goal 和五个候选方向，因此换地图后程序仍然能够运行，模型结构也不需要修改。

但是，当前权重是用 Map2 静态地图生成的特权 A* 标签训练出来的。Map2 的障碍尺度、通道宽度、密度和常见绕行形状已经进入模型的数据分布，所以 Map2 的 10/10 结果不能直接外推到另一张地图。

### 与 Map2 相近的地图

如果新地图只是改变障碍物位置，而下面这些条件基本不变：

- RGB-D 相机、视场角和点云质量；
- 飞行高度和最大速度；
- 障碍物尺度、密度和通道宽度；
- mission goal 距离；
- `35 m` 前瞻对应的实际绕行尺度；

那么可以先直接使用当前模型做零样本测试。GCN 仍会根据新地图实时生成的 topology graph 输出方向，后面的 A*、witness 和碰撞检查也会使用新地图的在线点云。

预期现象是：系统通常仍能规划，但离线方向准确率、路径效率和在线成功率可能比 Map2 下降，不能假设仍是 100%。

### 与 Map2 差异很大的地图

如果新地图包含更长的墙、更窄的通道、更密的森林、不同尺度的建筑，或者任务距离和飞行高度明显变化，就属于明显的分布变化。可能出现：

1. GCN 过度使用 Map2 中常见的绕行方向。
2. `35 m` 前瞻不足以覆盖更大的障碍，模型转向仍然偏晚。
3. 新地图的合理方向不符合 Map2 的五类分布，少数列准确率下降。
4. 候选方向虽然大致正确，但新地图没有对应的可达 topology frontier。
5. 下游 A* 或 witness 更频繁地否决 GCN 提议，表现为路线变长、重规划、停滞或超时。

GCN 选择方向错误不应直接产生一条穿障碍轨迹，因为 A* 和碰撞检查仍在下游；但这不构成绝对安全保证。局部地图不完整、控制跟踪误差或执行器接口失败仍可能造成碰撞。

### 当前模型中影响跨地图泛化的因素

有利因素：

- body-frame 相对位置和方向特征不依赖世界坐标轴朝向；
- mission goal 使用机体坐标表达；
- GCN 使用在线拓扑，而不是记忆一张固定栅格图；
- GCN 只提议 frontier 方向，几何验证仍由当前地图完成。

限制因素：

- 训练标签只来自 Map2 静态真值图；
- 输入仍包含归一化世界坐标，对地图范围和平移不是完全不敏感；
- `0.75 m` 栅格、`1.2 m` 膨胀和 `35 m` 前瞻是按当前场景设定的；
- 当前只有固定高度平面规划，未验证三维高度变化；
- 五个方向只有 `+40、+20、0、-20、-40` 度，不能表达急转或后退；
- 尚无跨地图、同配置的独立测试结果。

### 推荐的换地图验证流程

第一步是不训练，直接做零样本测试：

1. 导出新地图的静态点云，只用于离线评估，不提供给在线模型。
2. 使用当前 Map2 权重运行至少 10 到 20 个闭环 trial。
3. 记录成功率、碰撞率、超时率、路径长度、首次稳定绕行距离、方向切换次数和候选 witness 拒绝次数。
4. 用新地图静态点云重新计算离线 A* 真值，对比 GCN 五分类准确率和 Macro Accuracy。

如果零样本性能接近 Map2，可以继续使用原模型，但仍应保留新地图独立测试结果。

如果性能明显下降，则应重新生成特权数据：

1. 使用新地图完整静态点云生成占据栅格。
2. 按飞机尺寸膨胀障碍物。
3. 从各帧位置到 mission goal 运行 A*。
4. 根据新地图障碍尺度重新验证 `35 m` 是否合适，而不是默认沿用。
5. 将新地图数据加入训练集，并按 session 或地图划分训练、验证和测试集。
6. 在没有参与训练的新 session 上选择 checkpoint 和切换惩罚。
7. 最后重新运行闭环飞行测试。

### 训练策略选择

只有一张目标新地图时，可以在 Map2 检查点上微调，但必须保留一部分完全不参与训练的 session 做测试。

希望同一个模型用于多张地图时，更合理的方式是联合训练：

```text
Map2 + 新地图 A + 新地图 B
          ↓
按地图和 session 分组划分
          ↓
训练集地图 / 验证集 session / 未见地图测试
```

其中必须增加“整张地图留出”的测试：至少一张地图完全不参与训练，只用于检查真正的跨地图泛化。仅随机拆分同一张地图中的相邻帧会产生数据泄漏，得到的高准确率不能代表换地图能力。

### 换地图后的判断标准

不能只看普通 Accuracy。至少同时检查：

- 五分类严格准确率；
- Macro Accuracy，确认左右少数方向没有失效；
- 相邻一列以内准确率；
- 每个方向的混淆矩阵；
- GCN 方向切换率；
- A* 或 witness 对 GCN 候选的否决率；
- 最终闭环成功率、碰撞率和超时率。

换地图后的合理结论应该是：

> 模型结构可以直接复用，当前权重可以先做零样本测试；但权重是否可用必须由新地图的静态 A* 标签和闭环飞行共同验证。地图差异明显时，应重新收集特权标签并训练多地图模型。

## 针对当前审稿意见的处理

当前文稿能直接修正的部分已经按最新测试收口：

1. GCN 离线主结果只使用当前脚本可复现的 `89.3%` exact、`89.4%` macro、`99.4%` within-one 和 `0.115` column MAE；删除不可复现的 `91.3%/91.8%`。
2. 最新跨执行器批次保持为 YOPO `10/10`、EGO `7/10`、SUPER `8/10`。所有方法使用同一 Map2、同一起点 `(0,0,1.6)`、同一终点 `(0,140,1.6)` 和同一障碍序列；批次只是没有交错、逐 trial 配对采集。
3. 最新 EGO 三次失败均为碰撞，分别发生在执行 `31.30 m`、`83.41 m` 和 `132.15 m` 后；SUPER 为一次 `20.54 m` 早期碰撞和一次 `90 s` 超时。终止摘要不足以把根因归到 GCN、accepted witness 或 executor。
4. `no graph` 行只作为 direct-goal executor control，不宣称优于 occupancy-grid A*、RRT* 或其他全局规划器。
5. 固定 30 m 语义投影可能把假设放到表面后方或空中；已在 limitations 中明确当前没有 projection error 或 hypothesis rejection rate 的量化。

仅靠改论文无法解决的核心问题如下，投稿前应按优先级补实验：

1. **最高优先级：交错闭环。** 当前 runner 没有场景随机 seed；应继续固定同一地图、初态、目标和参数，按 trial 交错运行 GCN、hand-designed ranking 和 mission-goal-direction rule，避免整批次时间差。每组建议至少 30 次，报告 outcome 的置信区间。
2. **最高优先级：语义因果消融。** 在相同 reset 条件下交错运行 matched query、semantic disabled 和真正与场景无关的 query；另外冻结 graph snapshot，直接统计 edge-cost、selected branch 和 route switch 的变化。
3. **高优先级：强基线。** 增加在线 occupancy-grid/ESDF global planner；静态真值 A* 只能标为 oracle upper bound，不能作为同信息条件的普通基线。
4. **高优先级：失败链路归因。** 对每个失败同步对齐 GCN column、A* 接受/否决、witness clearance、local goal、executor command 和 collision/timeout，区分 route selection、route acceptance 与 tracking failure。
5. **必要的通用性验证。** 至少增加一张完全未参与训练的地图，以及一个允许高度变化的 3-D 场景；分别报告零样本 GCN 指标和闭环指标。

在这些实验完成前，论文可以成立的主张是“实现并验证了统一目标接口，且最新独立批次观察到成功率差异”；不能写成“统计证明 ScaleNav 优于强全局规划器”，也不能把完整系统的 `10/10` 单独归因于 GCN。

## 最终判断

模型结构的作用是：

- 让候选方向读取拓扑邻域，而不是只看单点分数；
- 让五个方向在同一个图上下文中比较；
- 用 GRU 保留上一帧选择，减少方向抖动。

但成功率从早期低水平提升到最终 10/10，主要由以下三项共同决定：

1. **标签改为静态全局 A* 的 35 m 前瞻方向。**
2. **训练和在线的 20 维机体坐标特征完全一致。**
3. **GCN 只做 frontier proposal，原有 A*、witness、碰撞检查和路线保持继续生效。**

如果只替换模型结构、不修正这三项，不能期待相同的成功率。
