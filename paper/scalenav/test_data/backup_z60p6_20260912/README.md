## 轨迹与日志诊断

1. **绕行侧别不同。** ScaleNav 从正 x 侧绕过障碍，最大 |x| 为 31.999/39.525 m；
   FAR 从负 x 侧绕行，最大 |x| 为 15.719 m。观测表面在初始路线附近呈现不对称的
   左右跨度；对这三条已完成轨迹而言，FAR 选择的一侧更省路。
2. **ScaleNav 很早就侧向承诺。** 两次首个前沿均约为 `(21.97,27.75,z)`，首个
   局部目标均约为 `(9.31,11.76,z)`。局部目标在 mission 起点之后 1.640/1.762 s
   出现，而第一帧非空障碍点云要到 3.170/3.270 s 才出现。FAR 首个局部目标直接
   指向 `(0,140,60.6)`，延迟约 0.010 s。提前侧向决策可能来自语义和前沿代价，
   不能仅凭这些日志认定它一定错误。
3. **中后段差异更大。** y=80..120 m 段，ScaleNav 两次走了 49.638/57.658 m，
   FAR 为 40.276 m。这一段的回摆值得优先分析；不仅是起步延迟。
4. **shortcut 已存在且运行。** `shortcutBubblePath()` 对候选路线做动态规划简化，
   新直线必须满足普通节点 bubble 覆盖和碰撞检查，不跳过中间虚拟语义节点。
   两次日志分别含 65/52 条 shortcut 消息，单次最多去掉 8/9 个节点。
   这些是日志消息数，不等于独立转弯次数。将路径简化成两点只会拉直到当前前沿，
   不会改变已经选定的绕行侧别或前沿终点。
5. **终点直达模式不是全程 LOS 检查。** 当前 `missionGoalWithinDirectHorizon()`
   使用 `max(goal_connect_distance, lookahead)`，默认约 15 m。两次日志在距离
   终点 14.72/14.44 m 时进入 `MISSION_DIRECT`；这个距离门限与“提前检测整段可直达”
   是不同机制。

## 对 shortcut 与 GCN 的判断

每次规划尝试连接更远的路线点或最终目标，是合理的改进方向。但必须区分：

- **当前路径内的折线冗余：** 现有 shortcut 已处理一部分。更强的可见性简化可以
  在已验证走廊里减少折线；不一定需要把临时捷径写成永久图边。
- **跨过障碍后继续追逐侧向前沿：** 可以增加“当前位姿到最终目标”的候选直线，
  与普通前沿竞争；通过自由空间覆盖、最新障碍物净空和执行器可行性检查后采用，
  并持续复核。无法验证到终点时，只沿目标方向推进到已观测的安全局部段。
- **一开始就选了更长的绕行侧：** shortcut 不能穿过障碍换边。GCN 有可能改善这一层
  的分支选择，但需要对应任务的训练/泛化能力与实测，不能从本次没有 GCN 的实验推断。

20 m 深度范围下，不能将“整条 140 m 线段没撞到当前点云”当作直达安全证明；
未观测区域可能有障碍。当前图中的障碍确实挡住初始起终点直线，故全程不转向的
假设不成立。合理目标是选更短的绕行侧，并在充分观测后及时直连，而非取消必要绕行。

建议按同一布局、传感器、速度和语义设置比较：当前手工前沿、手工前沿加已验证
直达候选、GCN 前沿加相同直达候选；分别统计路程、耗时、累计转向、碰撞和起步延迟。
这样能区分几何简化、前沿选边和启动等待的贡献。本次只归档、绘图和分析，未修改
规划算法，也未将这些结果加入论文正文。
