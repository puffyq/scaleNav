# Map2 Single-Run Validation

This directory contains a pipeline validation at the fixed Map2 mission:

- start: `(0.0, 0.0, 1.6)` m
- goal: `(0.0, 140.0, 1.6)` m
- goal radius: `0.5` m
- admissible arrival speed: `0.3` m/s
- date: 2026-08-28

`single_run_metrics.csv` is based on synchronized 100 Hz odometry and contains
one run for each method. This is a pipeline validation, not the final 20-trial
paired benchmark, and must not be used to claim aggregate success rates.

EGO-Planner and SUPER use the ROS2 Map2 adapters under
`bc/third_party/compare/`, the same simulator, RGB-D stream, odometry, dynamic
limits, collision handling, and `(0, 140, 1.6)` m goal. Their earlier logs
were archived with the suffix `invalid_wrong_map_20260828` after initial RGB-D
comparison showed that they were recorded in a different UE project. They are
excluded from this CSV and the paper table. The replacement runs were checked
at `(0,0,1.6)` m against YOPO's initial view: effective depth P05 was 4.180 m,
center depth was 6.637 m, and the ENU yaw was 89.95 degrees.

In the valid replacement runs, EGO-Planner collided at approximately
`(0.19,12.03,1.58)` m, 4.55 s after the goal event. Its reported path is
truncated at the first latched collision. SUPER completed the mission without
collision using the released 5 m/s trajectory limit, a 0.4 m vehicle radius,
and 0.4 m occupied-space inflation. Its synchronized result is 145.068 m in
30.556 s, with 4.748 m/s mean speed and 5.084 m/s peak speed.

The SUPER ROS2 configuration required one compatibility correction before the
valid run: the released ROS2 YAML used the unused keys `penna_max_acc_thr` and
`penna_min_acc_thr` for the backup optimizer, while the code reads
`penna_thr`. The corrected key and value match SUPER's released ROS1 YAML;
backup trajectories remain enabled and the 2.5 rad/s angular-rate bound is
unchanged. A separate requested 6 m/s-limit run, with the remaining official
7 m planning horizon and 4 m receding distance unchanged, collided with the
Map2 wall near `(7.17,81.40,2.12)` m. It is archived as a failed speed
condition and is not combined with the 5 m/s success row.

Collision handling was enabled and logged for EGO-Planner, SUPER, and the
selected ScaleNav run. The older YOPO validation run used a renderer with
`ignore_collision: true`, so its collision field remains `N/A`.
Kinematic-validity labels are not available for this four-run validation, and
safety is consequently `N/A` for every method.

The comparison plot is generated by `paper/scalenav/plot_speed_trajectories.py`.
Each regeneration archives any previous PNG/PDF in the sibling `history/`
directory before replacing the current output, so plot revisions remain
recoverable.
Its repeatable `--baseline LABEL=JSONL` option requires a goal-reaching log;
`--failed-baseline LABEL=JSONL` retains an auditable incomplete trajectory and
marks its endpoint with an X.
